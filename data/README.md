# Data provenance

Three kinds of artifact live here. Read this before reusing any of them.

## `medrag_eval.sqlite` — the ground-truth results database (53 MB)

Raw, append-only per-call logs for experiment `bench_315_v2`, created 2026-05-25.

| Property | Value |
|---|---|
| Logical calls | 2,520 = 315 questions × 4 models × 2 providers × 1 run |
| Tables | `experiments`, `datasets`, `questions`, `logical_calls`, `provider_attempts`, `parsed_answers`, `scores` |
| md5 | `c6eb43ede71c1c61ffa87f96e5e070f7` |
| Journal mode | WAL (sidecars are gitignored; they are recreated on open) |

**This file is the reproduction anchor.** Every published figure derives from it,
and it is treated as immutable — `rescore_with_fixed_parser.py` opens it with the
SQLite `mode=ro` URI and never writes back. If you modify it, you have left the
reproducible path; take a copy instead.

Verify integrity after cloning:

```bash
md5sum data/medrag_eval.sqlite   # macOS: md5 -q data/medrag_eval.sqlite
# expected: c6eb43ede71c1c61ffa87f96e5e070f7
```

### Privacy

The database contains **no credentials and no personal data**. This was verified,
not assumed — the full text of `request_json`, `request_headers_json`,
`response_body` and `error_message` across all attempt rows was scanned for bearer
tokens, API keys, passwords, email addresses, hostnames and URLs, with zero
matches. The harness is built to keep it that way: successful login response
bodies are dropped rather than persisted (`code/medrag_eval/providers/tailscale_medical_rag.py`),
`Authorization` is excluded from the persisted header set, and
`code/medrag_eval/logging_utils.py` redacts API-key-shaped strings.

The stored content is model output about public exam questions. No patient data
was ever in scope for this benchmark.

## `questions-ope-300-clean.xlsx` — the evaluation set (315 items)

Spanish-language multiple-choice items (4 options, single best answer) from the
Galicia (SERGAS) public-employment specialist examinations, specialty
*aparato digestivo*:

| Exam year | Items |
|---|---|
| 2016 | 105 |
| 2019 | 104 |
| 2022 | 106 |
| **Total** | **315** |

A conservative keyword scan of the question **stems** (`hepat*`, `cirros*`,
`colangi*`, `biliar*`, `varices`, `ascit*`) matches 58/315 = 18.4% as explicitly
hepatobiliary; including option-level mentions raises this to 88/315 (~28%). The
benchmark is therefore a *gastroenterology-and-hepatology* set in which hepatology
is a substantial minority, not half — results should not be generalised beyond
this exam domain.

## `statistical_analysis/` and `statistical_analysis_corrected/`

- `statistical_analysis/` — the **originally published** outputs. Committed
  unchanged; do not edit. Regenerating them requires the `analysis` extra and the
  staging step documented in `../reproduction.md` §D.
- `statistical_analysis_corrected/` — regenerated by
  `../rescore_with_fixed_parser.py` after the parser correction described in
  `../CORRECTION_NOTE.md`. Safe to delete and regenerate; the script is
  deterministic and rewrites it byte-identically.

Both are kept side by side on purpose, so the effect of the correction is
inspectable rather than asserted.
