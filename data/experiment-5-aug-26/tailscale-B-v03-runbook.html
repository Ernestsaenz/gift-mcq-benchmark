Running the Condition-B test with the v03 prompt

A manual procedure to swap the backend's stored prompt 13 for the v03 prompt and measure whether it improves GIFT (RAG) accuracy under the “none-of-the-above” transform — without trusting the B number alone.

Objective. Confirm that v03 — the prompt that genuinely improved Condition-B on the no-RAG proxy (+15 pp, with no cost to normal questions) — also lifts the GIFT/RAG arm on Condition B, where retrieved evidence ({chunks}) is available. This is the endgame the OpenRouter run only approximated.

01 Why v03, and why RAG should help more

Across ten of the hardest Condition-B questions, v03 was one of only two variants that raised B accuracy without hurting Condition A. It works by adding two short worked examples to the existing prompt — one whose answer is “Ninguna de las respuestas anteriores es correcta” and one whose answer is a real option. That balance is what stops the model from over-selecting the sentinel.

On GIFT the retrieved {chunks} give the model an independent way to establish the guideline-correct fact and check whether it is actually among the four options. The hypothesis: RAG evidence + v03's balanced demonstration should detect “the right answer is absent” more reliably than either piece alone.

02 The key mechanic (read this first)

How GIFT gets its instructions

On the GIFT/Tailscale arm the harness sends only the question and its four options in the user message. The instructions, the JSON contract, and the retrieval slot ({chunks}) all come from the server-side stored prompt 13. So the --prompt-version flag — and the OpenRouter-only run_variants.py from this experiment — do not change GIFT behavior. The only way to test v03 here is to replace prompt 13 in the backend.

Keep the injection points

The v03 GIFT form keeps the two placeholders the backend fills: {chunks} (retrieved context) and {question} (the question + options block), each exactly once. Do not rename or remove them, or retrieval / question injection will break.

03 Prerequisites

  • Access to the Tailscale/GIFT backend where stored prompt 13 can be edited manually, and the production backend is deployed and healthy (repo carneiran/handmade-gift).
  • Retrieval is live — {chunks} actually returns context. (If it returns empty, v03 gracefully falls back to clinical judgement, but you're then not testing RAG.)
  • GIFT credentials in .env: GIFT_API, GIFT_EMAIL, GIFT_PASSWORD.
  • The evaluation harness runs from the repo root with .venv/bin/python.
  • Test workbooks on hand: test-set/hard10-flat-B.xlsx and hard10-flat-A.xlsx (or a larger set — the full hard-200 / 500 for powered numbers).

05 Procedure

Back up the current prompt 13

Copy the existing stored prompt 13 text somewhere safe. This is your rollback and your baseline arm.

Verify the backend and retrieval

Confirm GIFT auth and that retrieval returns context. Run check-auth --provider tailscale and one probe question; confirm {chunks} is non-empty in the sent payload.

Import the test workbooks

Import hard10-flat-B.xlsx and hard10-flat-A.xlsx as two datasets (see commands below).

Run the BASELINE arm (prompt 13 unchanged)

Score Condition B and Condition A on GIFT with the current prompt 13. Name them gift_baseline_B / gift_baseline_A.

Swap prompt 13 → v03

In the backend, replace the stored prompt 13 body with the v03 text from step 04. Keep {chunks} and {question} intact. Save/deploy.

Verify the swap took effect

Re-run one probe question and confirm the served prompt now contains the EJEMPLOS RESUELTOS block.

Run the v03 arm

Score Condition B and A again, named gift_v03_B / gift_v03_A. Identical questions, identical everything except prompt 13.

Export and compare

Export all four experiments to CSV. Compute ΔB (v03 B − baseline B) and ΔA (v03 A − baseline A). See success criteria.

Restore or adopt

If v03 doesn't clear the bar, restore the backed-up prompt 13. If it does, keep v03 as the new prompt 13 and re-run at scale to confirm.

Sequence, don't parallelize

Because prompt 13 is a single global stored prompt, the baseline and v03 arms cannot run at the same time — they would hit the same served prompt. Finish both baseline runs, swap, then run both v03 runs.

07 Success criteria — read B and A together

v03 is a real improvement only if it lifts Condition B while holding Condition A. A B gain with an A drop is over-abstention, not robustness.

OutcomeΔBΔAVerdict
Genuine win↑ up≈ 0Adopt v03
Over-abstention↑ up↓ downReject — breaks normal items
No effect≈ 0≈ 0Keep baseline
What to expect

On the no-RAG proxy v03 gave B +15 pp, A +0. With retrieval feeding real evidence into the same balanced prompt, a larger B lift is plausible — that is the reason to test on GIFT at all. Watch the A number regardless.

Sample size

Ten questions × the backend model is a directional probe (each item moves the rate a lot). Treat a promising result as a signal, then re-run on the full hard-200 and the full 500 (both A and B) for a number you can report.

08 Cautions & rollback

  • Back up first. Keep the original prompt 13 text; rollback is a paste-back.
  • strict_json means no contract change. v03 keeps the 3-key JSON, so the backend's response validation and the harness parser are unaffected. (The reasoning variants v09/v10 would need the server to accept a 4-key object — v03 does not.)
  • Confirm retrieval isn't empty. If {chunks} comes back blank, you're measuring v03's parametric fallback, not RAG. Check a payload before trusting the numbers.
  • Change one thing. Keep model, temperature (0), question set, and top-k identical across the baseline and v03 arms so the only difference is prompt 13.
Rollback

To revert: paste the backed-up prompt 13 body back into the backend and re-verify with a probe question. No harness or database change is needed — results already written stay attributed to their experiment names.
